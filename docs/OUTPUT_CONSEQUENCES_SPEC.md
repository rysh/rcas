# 仕様：アウトプット／アウトカム分解からの帰結（OutputConsequences.lean）

著者の判断と依頼（2026-10-05）による。既存ファイルは書き換えない。

## A. 自走状態の条件③はアウトプットの意味（著者確認 2026-10-05）

§4.10 の③「成果 `q ≥ qMin`」を、`q t := output g (チーム側 t)`、`qMin := 1`、すなわち「タスク `g` を目的と基準どおりに達成している」と読む。

Phase 1 の `performance_not_derivable` は、③が Phase 1 の前提から導けないことを示していた。Phase 1 には、capability と成果 `q` をつなぐものがなかったからである。OutputOutcome.lean がそのつながりを与えるので、③（アウトプットの意味）は次の条件のもとで導ける。

- **SO1**：`1 ≤ output g s ⇔ MeetsCriteria g s`。
- **SO2（一度満たせば満たし続ける）**：ナレッジシェアのもとで、ある時刻に基準を満たせば、以後ずっと満たす。
- **SO3（いずれ満たす）**：次の条件がそろえば、いずれ基準を満たし、以後ずっと満たす。
  - シェアだけ（トップ固定）、伝達率に下限 `ηMin > 0`、`φ` は連続。
  - タスクの難易度が、シェアが行き渡ったときのフロンティア `frontier (fun _ => k 0 h) e`（＝ max_i k_h·e_i）より小さい。
  - タスクの量が、そのときの実効処理量 × 期間 `μ · (Σ e) · φ(k_h) · period` より小さい。
- **SO4（③を導いた SM1）**：SM1 の前提から③の仮定 `hq` を外し、代わりに SO3 の条件（タスクがチームの能力の極限の内側にあること）を置く。結論は、いずれずっと自走状態（③はアウトプットの意味）。

残る仮定は「上位から与えられたタスクが、チームの能力の極限の内側にある」ことである。これは成果そのものについての仮定ではなく、与えられたタスクの実行可能性についての条件になる（EMPIRICAL #33）。

## B. 努力に応じた利益配分は、責任の外の量に報酬を結びつける

利益を `outcome a s`（適合 × 潜在価値 × アウトプット）とし、OB2 の努力比例配分 `proportionalShare i e q` でそれを配るとする。著者のモデルには配分がない。ここで示すのは、配分を入れたらどうなるかの形式的な事実である。

- **AR1（報酬の差は上位が与える量だけから来る）**：
  - 上位から与えられる2つのタスクは、質（潜在価値・適合）も量（難易度・量・期間）も違ってよい。
  - チーム側は同じで、両方の基準を満たしているとする（チームの責任の範囲では同一）。
  - このとき同じ努力プロファイル `e` なら、報酬の差は `e i / (e 0 + e 1) · (fit·potentialValue − fit'·potentialValue')` になる。チーム側の値は差に入らない。
- **AR2**：さらに `e i > 0` なら、報酬が等しい ⇔ `fit·potentialValue = fit'·potentialValue'`。特に同じタスクなら、適合が違えば報酬が違う。同じ努力・同じアウトプットでも、チームが責任を負えないタスクの質・量・適合によって報酬が変わる。
- **AR3（配る総額は上位が決める）**：基準を満たした後は、チーム側をどう改善しても、努力の配分キーをどう変えても（総努力 > 0）、配る総額は `fit · potentialValue` で一定である。努力は取り分の比率を変えるだけで、総額を増やさない。

## 位置づけ

B は「努力に応じた利益配分が適切でない」という著者の判断を支える、モデル内の事実である。「適切かどうか」という評価そのものは著者の判断であり、Lean では述べない。B は次の前提に依存する。

- アウトカムが掛け算の形であること（#30）
- タスクの質（潜在価値・適合）と量が上位から与えられること（#32）

利益の変動（NA1–NA3）とアンダーマイニング（前提 #28）は、別の理由として NoAllocation.lean にある。
