# 仕様：capability → アウトプット → アウトカムと責任の範囲（OutputOutcome.lean）

著者の依頼（2026-10-05）による拡張。既存ファイルは書き換えない。

## 著者の構造

タスク（難易度・量）・capability → アウトプット → アウトプット・ビジネス適合 → アウトカム

- 目的と基準は上位から与えられる。チームはタスクの質（目的と基準がビジネスに適合しているか、タスクが内在する価値）には責任を負えない。
- チームが責任を持てるのは次の3つ。
  - タスクの達成
  - タスクを効率よく実行するための仕組みの改善
  - 自分たちの能力開発による capability の向上
- アウトプットは、目的と基準を満たしている限り一定である。
- アウトカムは、目的と基準がビジネスにどのくらい適合しているかで変動する。ただし、タスクが元々内在している価値を超えることはできない。

## 定式化

| 層 | Lean | 誰が決めるか |
|---|---|---|
| タスク：基準が求める水準 `difficulty`、量 `workload > 0`、期間 `period ≥ 0`、内在価値 `value ≥ 0` | `Task` | 上位 |
| ビジネス適合 `fit ∈ [0, 1]` | `GivenFromAbove`（`task` と `fit`） | 上位 |
| capability：フロンティア `frontier`、処理量 `throughput`、仕組みの効率 `mechanism` | `TeamSide` | チーム |
| アウトプット：目的と基準どおりに完了した割合 | `output` | 両者から決まる |
| アウトカム = `fit × value × output` | `outcome` | 両者から決まる |

- **アウトプット** `output g s`：
  - `frontier < difficulty` なら 0（基準の水準に誰も届かない）。
  - そうでなければ `min 1 (mechanism · throughput · period / workload)`（期間内に終えられる割合）。
  - 値は `[0, 1]` に入る。
- **目的と基準を満たす** `MeetsCriteria g s`：`difficulty ≤ frontier` かつ `workload ≤ mechanism · throughput · period`。
- **Performance.lean との接続**：`frontier` には `frontier k e`（能力×エンゲージメントの最大）を、`throughput` には `volume φ k e` を入れる。

## 定理

### アウトプット
- **OP1**：`output ∈ [0, 1]`。`output = 1 ⇔ MeetsCriteria`。
- **OP2（一定）**：基準を満たしていれば、capability や仕組みをさらに上げてもアウトプットは 1 のまま。
- **OP3（単調）**：アウトプットはフロンティアと実効処理量（`mechanism · throughput`）について単調。

### アウトカム
- **OC1（内在価値を超えない）**：`outcome ≤ fit · value ≤ value`。
- **OC2（適合で変動）**：基準を満たしていれば `outcome = fit · value`。`value > 0` なら、適合について狭義単調。

### 責任の範囲
- **RS1（チームが到達できる上限）**：どんなチーム側の値でも `outcome ≤ fit · value`。`fit · value > 0` のとき、等号 ⇔ 基準を満たす。この上限は上位が決める量だけでできている。
- **RS2（不足分の帰属）**：基準を満たしていれば、内在価値との差 `value − outcome = (1 − fit) · value` は、チーム側の値によらない。
- **RS3（同じチームでの差は上位側から来る）**：チーム側と基準（難易度・量・期間）が同じなら、アウトカムの差は `(fit·value − fit'·value') · output` で、上位が決める量の差だけで決まる。
- **RS4（基準を満たした後の改善はアウトカムを変えない）**：基準を満たした後に capability や仕組みを上げても、アウトカムは変わらない。変わるのは必要時間 `workload / (mechanism · throughput)` で、これは単調に減る（効率）。

### 能力開発との接続（Performance.lean）
- **CP1**：ナレッジシェアのもとでは、同じタスクのアウトプットは時間について単調非減少で、必要時間は単調非増加（PV1・PS3 から）。
- **CP2**：シェアだけ（トップが学ばない）なら、初期の能力の上限を超える難易度のタスクのアウトプットは、ずっと 0 のまま（PS2 から）。担える難易度が広がるのは、上限が上がるとき（トップ自身の学習 PM1、専門化 OM3）に限る。
- 安定性との関係：任意の m 人が抜けても難易度 `d` の基準に届く人が残る ⇔ `d` の水準を担える人が m 人より多い。これは PR1 で `θ = difficulty` とした場合そのもの。

## 前提として置くもの・範囲外

- アウトカムが `fit × value × output` の掛け算の形であること（前提。EMPIRICAL に置く）。
- `fit`・`value` の測り方、タスクの質そのもの。
- アウトプットを「完了割合」で測ること。基準を超える出来栄えは、アウトプットにもアウトカムにも数えない（「一定」の定式化）。
