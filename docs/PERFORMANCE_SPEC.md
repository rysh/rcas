# 仕様：ドメイン別パフォーマンスとナレッジシェア（拡張）

著者の依頼（2026-10-04）による拡張。指示書 §4・§5 にはない項目で、Phase 1・2 のファイルは書き換えない。実装は `RCAS/Performance.lean`。

## 表現したいこと（著者）

- チームのパフォーマンスは、ドメインごとに「いちばん能力の高い人の能力とエンゲージメント」が上限になる。
- 他のメンバーとのナレッジシェアが進むにつれて、アウトプットの量と安定性が上がる。

「パフォーマンス」を1つの変数に潰さず、ドメインごとに **フロンティア F・量 V・安定性 S** の3成分に分ける。

## 記号（1つのドメイン d について。添字 d は省略）

| 記号 | Lean | 意味 | 前提 |
|---|---|---|---|
| `k t i` | `k : ℕ → ι → ℝ` | 時刻 t のメンバー i の能力 | `0 ≤ k 0 i` |
| `e i` | `e : ι → ℝ` | メンバー i のエンゲージメント | `0 ≤ e i ≤ 1` |
| `h` | `h : ι` | このドメインで最も能力の高いメンバー（同点ならどれか1人） | `∀ i, k 0 i ≤ k 0 h` |
| `C(t) = max_i k t i` | `ceiling` | 能力の上限（トップの能力） | — |
| `F(t) = max_i k t i · e i` | `frontier` | フロンティア：チームの誰かが実際に出せる最高水準（著者選択） | — |
| `V(t) = Σ_i e i · φ (k t i)` | `volume` | アウトプットの量 | `φ` は単調非減少 |
| `carriers(t) = {i ∣ θ ≤ k t i · e i}` | `carriers` | そのドメインの仕事を十分に担える人 | — |
| `N(t) = #carriers(t)` | `(carriers ..).card` | 担える人数 | — |
| 安定性 S | `ToleratesLoss m` | 任意の m 人が抜けても、担える人が残る | — |

## ナレッジシェアの力学（前提。構造体 `KnowledgeSharing` のフィールド）

- 追いつき：`i ≠ h` について `k (t+1) i = k t i + η t i · (k t h − k t i)`
- 伝達率：`0 ≤ η t i ≤ 1`
- トップは下がらない：`k t h ≤ k (t+1) h`（相互学習でトップ自身が伸びることも許す）
- 初期にトップ：`∀ i, k 0 i ≤ k 0 h`

「シェアだけ（トップ自身は学ばない）」は追加の仮定 `∀ t, k (t+1) h = k t h` で表す。

`η` が結合（§5.3）やファシリテーション、ペアリング、レビュー、ADR などにどう依存するかはモデル化しない（`docs/EMPIRICAL.md`）。

## 定理

### 静的な関係（フロンティア）

- **PF1**：`k h · e h ≤ F ≤ C`（`0 ≤ k`、`0 ≤ e ≤ 1`）。フロンティアの上限はトップの能力で、下限はトップ本人の実効水準。
- **PF2**：トップが十分に関わっていれば（`e h = 1`）、`F = C`。

### ナレッジシェアのもとで

- **PS1（トップはトップのまま）**：すべての t で `C(t) = k t h`。
- **PS2（フロンティアの保存）**：シェアだけなら、すべての t で `C(t) = C(0)`、`F(t) ≤ C(0)`。シェアだけでは上限は上がらない。
- **PS3**：実現されるフロンティア `F(t)` は単調非減少で、`C` を超えない。トップのエンゲージメントが低い場合に、他のメンバーが追いつくことで `F` が上限に近づく余地がある。
- **PM1（相互学習によるフロンティアの拡大）**：`C(t) < C(t+1)` ⇔ `k t h < k (t+1) h`。上限が上がるのはトップ自身が学ぶときに限る。
- **PV1（量の増加）**：`V(t)` は単調非減少。
- **PV2（量の厳密な増加）**：ある `i ≠ h` で `η t i > 0`、`k t i < k t h`、`e i > 0`、かつ `φ` が狭義単調なら `V(t) < V(t+1)`。
- **PV3（量の極限）**：シェアだけ、`η t i ≥ ηMin > 0`（`i ≠ h`）、`φ` が連続なら、`k t i → k 0 h` で、`V(t) → (Σ_i e i) · φ (k 0 h)`。全員がトップの水準でできるようになった量に近づく。
- **PR1（安定性の意味）**：任意の m 人が抜けても担える人が残る ⇔ `m < N`。
- **PR2（安定性の増加）**：`carriers(t)` は包含について単調、したがって `N(t)` は単調非減少で、一度得た耐性は失われない。
- **PR3（安定性の到達点）**：シェアだけ、`η ≥ ηMin > 0`。エンゲージメントは時刻ごとに変わってよく、`e t i ≥ eMin i` だけを仮定する。このとき、いずれ `{i ∣ θ < k 0 h · eMin i} ⊆ carriers(t)` となる。そのような人が m 人より多ければ、いずれ任意の m 人の離脱に耐える。
- **PT1（チーム全体）**：`P(t) = Σ_d w d · Ψ (F_d(t)) (V_d(t)) (N_d(t))`（`w ≥ 0`、`Ψ` は各引数について単調）は、全ドメインでナレッジシェアが働けば単調非減少。

### 具体例

1人の専門家（`k 0 = (1, 0, 0)`、`e = 1`、`θ = 1/2`、`η = 1/2`）から1歩で：

- `F`：1 → 1（変わらない）
- `V`（`φ = id`）：1 → 2
- `N`：1 → 3（専門家1人だけの状態では、その人が抜けると担える人がいなくなる。1歩後は誰か1人が抜けても残る）

## 範囲外・前提として置くもの

- `η`・`φ`・`Ψ`・`θ` の具体的な形や値、およびそれらが現実の組織で成り立つか。
- PF・PS・PV1・PV2・PR2 ではエンゲージメント `e` を時間について固定する。ナレッジシェアの効果だけを取り出すためである。エンゲージメントが変動する場合は PR3 の形（下限 `eMin` だけを仮定）で扱う。
- 安定性を確率（「離脱後もドメイン能力が残る確率」）として扱う版は扱わない。`ToleratesLoss` と `N` で表す。
